## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:


- [Library results](#library-results) - What was located, summarized and built for each library, and the merged metrics
- [Pipeline information](#pipeline-information) - Report metrics generated during the workflow execution, and the record of what each library was processed from





### Library results

<details markdown="1">
<summary>Output files</summary>

The merged results are flat in the output directory. The per-library records that are published are in directories of their own. Everything else a library
produces (its metrics row, its joined and filtered cell metadata, its MapMyCells TSV, its arguments file) stays in the work directory.

- `<analysis>.library_metrics.txt` - the library metrics of all libraries, in manifest order.
- `<analysis>.cell_metadata.txt` - the cell metadata of all libraries (in manifest order), indexed by `PREFIX` and `cell_barcode`.
- `matrix.mtx.gz`, `barcodes.tsv.gz`, `features.tsv.gz` - the sparse DGE of all libraries (barcodes are `<library>_<cell barcode>`).
- `<analysis>.cell_type_column.txt` - the name of the cell type column (only if the libraries have MapMyCells results).
- `<analysis>.donor_cell_type.txt` - cells and median UMIs per donor and cell type (only with donors and a cell type column).
- `<analysis>.donors.metacells.txt.gz` - expression summed per donor (only with donors).
- `<analysis>.donor_cell_type.metacells.txt.gz` - expression summed per donor and cell type (only with donors and a cell type column).
- `artifacts/<library>.yaml` - the artifacts found for each DGE of the manifest.
- `tearsheets/<library>.standard_analysis_tearsheet.txt` - the tearsheet of each library.

Either all libraries have donors (a `donor` in the manifest entry, or a village in the artifacts) or none do; a mix stops the run. Without donors, or without a
cell type column, the steps that need them are skipped with a warning.

</details>

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Parameters used by the pipeline run: `params.json`.
  - `<analysis>.resolved_libraries.txt`: plain text record of what each manifest entry resolved to (per library: DGE, cell metadata, MapMyCells result, extra files and `join_and_filter_tsv` arguments).

</details>

[Nextflow](https://www.nextflow.io/docs/latest/tracing.html) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
